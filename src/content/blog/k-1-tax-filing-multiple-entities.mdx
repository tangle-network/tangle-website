A late or corrected K-1 can invalidate draft amounts, state workpapers, and loss calculations when the workflow lacks document versioning and dependency tracking.
The taxpayer has a partnership Schedule K-1 from a fund, an S corporation Schedule K-1 from a company they own, a corrected statement from an operating partnership, and a page of state or international footnotes.
Entering the visible box amounts into a tax program feels like progress.
Without source identifiers, a page inventory, and attachment checks, box entry can hide duplicates, omissions, loss limits, and superseded statements.

A **Schedule K-1** is a tax schedule that an entity gives an owner or beneficiary to report that person’s share of income, deductions, credits, and other items.
The form is not one universal document.
Schedule K-1 (Form 1065) comes from a partnership, Schedule K-1 (Form 1120-S) comes from an S corporation, and Schedule K-1 (Form 1041) can come from an estate or trust.
The current [partner instructions for Schedule K-1 (Form 1065)](https://www.irs.gov/instructions/i1065sk1) and [Form 1120-S instructions](https://www.irs.gov/instructions/i1120s) are the references for their respective forms.

In this series, **Tangle Tax Agent** means a proposed workflow that inventories tax records, maps attached statements, prepares reconciliation workpapers, and waits for review before a filing decision.
It keeps one Tangle sandbox, a Linux machine, per client.
Every total is computed by code run in that sandbox, and nothing is filed until a person approves the draft.

## Reconcile each K-1 against its entity, year, and attachments

The first task is to determine what each K-1 represents before adding any amount to a return.

| K-1 source | What it reports | Why the source identity matters |
| --- | --- | --- |
| Partnership K-1 (Form 1065) | A partner’s share of partnership items | Partnership basis, liabilities, activity grouping, and attached statements can affect the partner-level result |
| S corporation K-1 (Form 1120-S) | A shareholder’s pro rata share of S corporation items | Stock basis, debt basis, distributions, and shareholder-level limits remain separate questions |
| Estate or trust K-1 (Form 1041) | A beneficiary’s share of items reported by the fiduciary | The reporting path and attached statements differ from a partnership or S corporation |
| K-2 or K-3 attachment | International information from certain partnerships or S corporations | Foreign tax and international items may require additional forms or review |

The IRS says a partnership uses Schedule K-1 to report each partner’s separate share, and its partner instructions cover passive-activity, basis, and other limits.
The [2025 Form 1065 instructions](https://www.irs.gov/instructions/i1065) also require activity detail so partners can apply the passive-activity rules.

The S corporation instructions also state a separate boundary.
They say the K-1 reports the shareholder’s separate share, while basis, at-risk, and passive-activity limits are set at the shareholder level.
The number in the box is an input to the return, not the final deductible amount.

## Example: Priya’s Harbor, Cedar, and Northstar records

Imagine Priya, a founder and angel investor, receives the following records for one tax year.
The sample figures are illustrative, not a tax calculation.

| Source | Visible amount | Attached detail | First review question |
| --- | ---: | --- | --- |
| Harbor Software S corporation K-1 | $80,000 ordinary income | $35,000 non-dividend distribution and state information | Does the shareholder basis workpaper support the distribution and any related loss items? |
| Cedar Ventures partnership K-1 | $42,000 ordinary income | State apportionment footnote and a capital-gain statement | Which items go to federal, state, and capital-gain schedules? |
| Northstar Fund partnership K-1 | ($18,000) loss | Passive-activity statement and an international-information request notice | Is the loss passive, limited, or waiting for international information? |
| Northstar corrected K-1 | $9,000 replacement loss | Revised statement issued two weeks later | Which draft lines, estimates, and state workpapers changed? |

The arithmetic alone is tempting:

```text
$80,000 + $42,000 - $18,000 = $104,000
```

That total is not a valid return input.
The Northstar correction may replace the earlier $18,000 loss rather than add another item.
The Harbor distribution is not the same category as its K-1 income.
The Cedar capital-gain statement may need a separate reporting path.
The Northstar passive-activity statement may limit the current-year use of the loss.

The software should therefore create one record per source and one reconciliation entry per relationship.
It should never flatten every K-1 into a single “other income” bucket.

An agent may state a total, but the total counts only after code computes it.
The check below runs in Priya's sandbox.
`client.instances.ensure` returns the sandbox kept under her key, and `box.exec` runs the script and returns its exit code and output.
The script fails unless the Northstar correction is exactly $9,000.

```ts
import { Sandbox } from "@tangle-network/sandbox";

const client = new Sandbox({
  apiKey: process.env.TANGLE_API_KEY!,
  baseUrl: "https://sandbox.tangle.tools",
});

// One sandbox per client, kept under this key.
const instance = await client.instances.ensure({
  key: "client:priya",
  create: { resources: { cpuCores: 1, memoryMB: 2048, diskGB: 10 } },
});
await instance.box.write("/home/agent/k1_totals.py", `
k1s = {  # (entity, version): ordinary income or loss
    ("Harbor Software", 1): 80000,
    ("Cedar Ventures", 1): 42000,
    ("Northstar Fund", 1): -18000,
    ("Northstar Fund", 2): -9000,  # corrected K-1
}
latest = {}
for (entity, version), amount in sorted(k1s.items()):
    latest[entity] = amount  # sorted by version, so the corrected K-1 wins
print("every row added:", sum(k1s.values()))
print("latest versions:", sum(latest.values()))
change = latest["Northstar Fund"] - k1s[("Northstar Fund", 1)]
assert change == 9000, f"expected a 9000 correction, got {change}"
print("Northstar change:", change)
`);
const { exitCode, stdout } = await instance.box.exec("python3 /home/agent/k1_totals.py");
console.log(exitCode, stdout);
```

The script exits 0 and prints:

```text
every row added: 95000
latest versions: 113000
Northstar change: 9000
```

Adding every row counts Northstar twice.
Keeping only the latest version gives $113,000, and the assertion confirms the $9,000 change.
That figure is a box total for the source index, not a return input, for the reasons above.

## Reconcile the corrected K-1 before adding it

A **final K-1** reports the entity’s final position for the relevant period.
An **amended K-1** corrects or changes a previously issued statement.
Northstar's original statement reported an $18,000 loss, and the corrected statement reported $9,000.
The application should treat the second document as a new version of the same entity-and-year record, not as another loss.

| Version | Ordinary loss | Product action | Downstream review |
| --- | ---: | --- | --- |
| Original K-1 | ($18,000) | Store the source and map its attached statement | Check whether a draft or estimate already used it |
| Corrected K-1 | ($9,000) | Mark the original superseded and compare source pages | Recalculate affected federal, state, passive-activity, and estimate workpapers |
| Reviewer decision | ($9,000) or an unresolved value | Record who accepted the correction and when | Preserve the prior draft and the reason for the change |

The difference is a $9,000 reduction in the reported loss, but that is not automatically a $9,000 increase in currently usable income.
The passive-activity statement, basis, state allocation, and any K-3 information still travel with the corrected version.

The IRS partner instructions also warn against combining prior-year limited amounts with current-year K-1 amounts as one current-year figure, except where they provide a different treatment for passive activity items.

A stable source identifier should combine the entity, form type, tax year, and version, while each extracted item should retain its page reference.
Northstar's record keeps both versions and the changed field:

```json
{
  "entity": {
    "name": "Northstar Fund",
    "type": "partnership",
    "form": "Schedule K-1 (Form 1065)",
    "taxYear": 2025
  },
  "sourceVersions": [
    {
      "id": "northstar-original",
      "status": "superseded",
      "document": "northstar-k1-original.pdf",
      "receivedAt": "2026-02-21"
    },
    {
      "id": "northstar-amended",
      "status": "needs-review",
      "document": "northstar-k1-amended.pdf",
      "receivedAt": "2026-03-04"
    }
  ],
  "changes": [
    {
      "field": "ordinary-loss",
      "from": -18000,
      "to": -9000,
      "source": "northstar-amended#page=2"
    }
  ],
  "openQuestions": [
    "Confirm passive-activity treatment.",
    "Review the international-information request notice and attachment."
  ]
}
```

## The source index is the first deliverable

A source index records what arrived, what the document claims to be, and whether its supporting pages were included.
For each K-1, retain the entity name, federal identification number when present, tax year, entity type, issue status, upload version, and attached statements.

The index should also track expected forms.
If Priya tells the system that Northstar normally issues a K-1 but the file is missing, the return should show an expected document rather than look complete.
The taxpayer can then request the form, ask an advisor whether to extend, or record a documented decision to proceed.

These states apply to each source:

| State | Meaning |
| --- | --- |
| Received | The file opened and appears to belong to the stated entity and tax year |
| Candidate | The system extracted a value or relationship that still needs confirmation |
| Accepted | A reviewer accepted the source and mapping for this draft version |
| Superseded | A later corrected or final statement replaced the earlier source |
| Missing | The expected document did not arrive |
| Blocked | A downstream calculation cannot proceed without a fact or review decision |

An empty field and a confirmed zero are different states, and the index should keep them apart.

## Attached statements add facts beyond the face of the K-1

Attached statements can contain activity descriptions, state amounts, foreign taxes, capital gains, partner liabilities, special allocations, and instructions for where an item belongs.

The software should extract those attachments as separate records.
It should link each extracted candidate to the page and preserve the original wording beside any normalized amount.

The IRS partner instructions say that under passive-activity rules, the partner uses activity information and forms or worksheets to determine what is currently reportable.
The software should therefore keep each activity separate until the partner-level calculation is reviewed.

**Passive activity** is an activity whose income or loss is subject to special limits because the taxpayer did not materially participate under the applicable rules.
**Material participation** is a fact-based standard about the taxpayer’s involvement in the activity.
The agent should ask for the facts or preserve an advisor question rather than infer material participation from the taxpayer’s job title.

**Basis** is the taxpayer’s tax investment in an entity interest.
It can change with contributions, allocated income or loss, distributions, liabilities, and other facts.
Basis is not the same as the cash the taxpayer received.

The current [IRS Publication 541](https://www.irs.gov/publications/p541) explains that partnership distributions and partner basis interact, and the [S corporation stock and debt basis guidance](https://www.irs.gov/businesses/small-businesses-self-employed/s-corporation-stock-and-debt-basis) explains the corresponding shareholder issue for S corporations.

## Federal boxes do not settle state or international work

K-1 packages often include state footnotes because an entity’s income may be sourced, apportioned, withheld, or reported differently across jurisdictions.
The software should preserve those items in a state matrix.

| State record | Review question |
| --- | --- |
| State income or loss | Which state and activity does the amount describe? |
| State withholding | Does the payment belong to Priya, the entity, or another owner? |
| Composite or nonresident filing notice | Is a separate state filing or credit question raised? |
| State apportionment percentage | Is it a rate, an allocation, or a source description? |
| Amended state statement | Which estimated payment, return line, or filing deadline changes? |

For the entity and owner views, Schedule K-2 reports relevant items at the partnership or S corporation level, while Schedule K-3 reports the owner’s share of those items.
The current [2025 partnership K-2 and K-3 instructions](https://www.irs.gov/instructions/i1065s23) and [2025 S corporation K-2 and K-3 instructions](https://www.irs.gov/instructions/i1120s23) should be linked to the relevant workpaper.

The software should not treat an international-information request notice as proof of a final foreign tax result.
It should mark the international item as pending and identify what statement or advisor decision is missing.

## Make correction history the Tangle output

The proposed Tangle Tax Agent workflow treats multiple K-1s as one reconciliation session:

```text
collect expected and received K-1s
-> identify entity type, tax year, and version
-> extract boxes and attached statements with page links
-> build basis, activity, state, and international workpapers
-> compare amended or duplicate documents
-> list unresolved questions and affected return lines
-> obtain approval before the filing package is finalized
```

The agent should link sources, attachments, versions, open questions, and affected return lines into one review packet in the client's sandbox.

## What the software cannot decide

A readable K-1 is not a correct K-1, and a completed run does not certify that the taxpayer applied every limitation.
The software cannot establish material participation, a complete basis workpaper, or a state allocation from a federal footnote alone.
It should not decide that a loss is deductible, a state footnote is irrelevant, or an amended K-1 can be ignored.
It cannot recover a missing K-1 from a guess; it records the expected document, shows which calculations are blocked, and hands the questions to an advisor.
This is not tax advice, and multiple K-1s can require professional review, especially with basis, passive activity, foreign information, ownership changes, or amended statements.

## Choose reconciliation over data entry

Use K-1 tax filing software for multiple entities only when it preserves each source document and attachment, tracks entity type and tax year, separates basis and activity questions, keeps state and international details visible, and versions amended statements.
If the product offers one combined total with no source-to-line map, it is an entry shortcut rather than a review system.
If one entity supplies a complete, unchanged K-1 with no material attachments, conventional filing software may be enough.

## What should I inspect before filing?

Inspect the K-1 source index, attached statements, duplicate and correction log, basis and activity workpapers, state matrix, K-2 or K-3 items, open questions, and draft return mapping.
