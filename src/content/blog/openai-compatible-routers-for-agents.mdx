Every prompt your agent sends, and every tool call it is about to run, passes through the base URL you gave it.
When that URL is a router, the router decides which model answers, which of your fields reach it, how often a failed call is retried and billed, and who else reads the traffic, and a normal OpenAI-compatible response tells you none of it.

The bad case is on record.
In April, researchers ran a coding agent through 428 LLM API routers they had bought from resellers or collected from public lists: nine injected malicious code into the tool calls they returned, and seventeen touched AWS credentials the researchers had planted in the traffic ([Liu et al., "Your Agent Is Mine"](https://arxiv.org/abs/2604.08407)).
Honest routers fail more quietly.
In August our own router, Tangle Router, answered requests for `gpt-5.5` with `gemini-2.5-flash` at HTTP 200, because one of our OpenAI projects had hit its spend limit.
Every one of our products whose default named an OpenAI model ran on Gemini.
The response body said `gemini-2.5-flash`, but nothing failed, the catalog and the status page both read healthy, and only comparing the model that answered with the model that was asked for found it.

We made substitution opt-in the same day, and we wrote down the questions we should have asked of our own router.
They apply to any OpenAI-compatible router: OpenRouter, a LiteLLM proxy you host, Portkey, or ours.
Each one below comes with the request that answers it and what Tangle Router answered on 17 November 2026, including the answers that do not flatter it.

## Switching is one base URL; the behavior is not

"OpenAI-compatible" describes a request and response shape.
Point the OpenAI SDK at `https://router.tangle.tools/v1` for `/v1/chat/completions` and `/v1/responses`, or the Anthropic SDK at `https://router.tangle.tools` for `/v1/messages`, with a Tangle key that one approval by the account owner issues and that works only for the Tangle products that owner approved.

```js
import OpenAI from 'openai'
import Anthropic from '@anthropic-ai/sdk'

const openai = new OpenAI({ baseURL: 'https://router.tangle.tools/v1', apiKey: process.env.TANGLE_API_KEY })
// authToken, not apiKey: the router accepts the key only as a Bearer token today
const anthropic = new Anthropic({ baseURL: 'https://router.tangle.tools', authToken: process.env.TANGLE_API_KEY })
```

The Anthropic SDK's `apiKey` option sends the key in an `x-api-key` header, and on 17 November Tangle Router answered that with 401 `invalid_credentials`; the same `/v1/messages` request for `openai/gpt-4o-mini` with `Authorization: Bearer` answered 200.
An agent can request a key itself with the [setup skill](https://router.tangle.tools/agent-setup.md) and hand the owner one approval link.

What the shape does not promise is that the same model answers, that every field you send reaches it, or that a failure is reported the way the provider would report it.

## 1. Which model answered this request?

The body's `model` field is the first place to look.
OpenRouter returns the model it used there ([model fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks)); a LiteLLM proxy adds an `x-litellm-model-id` header naming the deployment that served ([reliability](https://docs.litellm.ai/docs/proxy/reliability)).

Tangle Router puts both sides on a chat response, and also names the substitute it was not allowed to use:

```text
POST /v1/chat/completions  {"model": "openai/gpt-4o-mini", ...}
200
x-tangle-requested-model: openai/gpt-4o-mini
x-tangle-served-model: openai/gpt-4o-mini
x-tangle-refused-substitutes: google/gemini-2.5-flash-lite
```

The substitute it ranked for an OpenAI model was another vendor's model, which is why substitution is off by default.
The [setup skill](https://router.tangle.tools/agent-setup.md) tells agents to compare the requested and served headers, and your code should too, because nothing else fails when they differ.

Two cases need more care.
A stream sends its headers before the router knows which model will finish it, so streams carry no served-model header; read `model` from the last chunk, the one with usage, not the first (question 2 shows why).
A `/v1/responses` request for an OpenAI model goes to OpenAI untouched and comes back with OpenAI's own headers and dated model id (`gpt-4o-mini-2024-07-18`), without the router's headers.

## 2. Will it answer with a model you did not ask for?

There are three ways a different model can answer.

- **Your own fallback list.** OpenRouter, Portkey, LiteLLM and Tangle Router all accept an ordered list of fallback models (`models` on OpenRouter and on ours). That is a substitution you asked for, and the answer still comes back at HTTP 200.
- **A router-picked substitute.** Until August, Tangle Router could add a model nobody named when the requested one failed. That is the `gpt-5.5` incident above.
- **The same model on another provider.** OpenRouter routes one model across several providers and, by default, falls back to another provider when the first is unavailable ([provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)). OpenRouter's own measurements found that tool-call accuracy for the same model "vary between providers significantly more than the standard benchmarking would suggest" ([Exacto](https://openrouter.ai/blog/announcements/provider-variance-introducing-exacto/)), so the same name is not always the same behavior.
  Tangle Router does this too, by default, for some models named by their maker (`anthropic/` and `xai/` ids among them): when the direct provider is out of quota, refuses the router's credential, is rate limited or is down, the same request goes once to OpenRouter, pinned to the maker's own endpoint there. `allow_fallbacks` and `require_model` do not turn this off; `provider.ignore: ["openrouter"]` does, and so do a `max_price` ceiling, a data-residency requirement or your own provider key.

On Tangle Router, the second kind is off unless you send `provider.allow_fallbacks: true` ([routing guide](https://router.tangle.tools/docs/guides)).
`require_model: true` (or the `x-tangle-require-model` header) goes further and refuses any model the router picks, including a renamed version of the one you asked for.
Your own `models` list is a separate choice: it is tried in order even with `require_model` set, so when exactly one model may answer, send no list.
`provider` takes `order`, `only`, `ignore` and `max_price` preferences for the providers behind each model, with the same names OpenRouter uses (not always the same behavior; see `max_price` below).
Whatever you set, compare `x-tangle-served-model` with the model you asked for and reject a response your code did not plan for.

Here is a fallback you asked for, on a stream: Gemini first, `gpt-4o-mini` as the fallback, and a one-second deadline for the first token.

```text
{"model": "google/gemini-2.5-flash", "models": ["openai/gpt-4o-mini"], "stream": true,
 "provider": {"first_token_timeout": 1000}, ...}

1,196 ms  headers and first event   {"model": "google/gemini-2.5-flash", "delta": {"role": "assistant"}}
1,783 ms  next event                {"model": "openai/gpt-4o-mini", ...}
1,816 ms  "46", then usage          every chunk "openai/gpt-4o-mini"
```

Gemini had not produced a token by the deadline, so `gpt-4o-mini` wrote the answer.
The opening event carries no text and the router's own generation id, so the router wrote it, and it still names Gemini; a client that logs the model from the first chunk records the wrong one.
The same request with `require_model: true` was also answered by `gpt-4o-mini`, because `gpt-4o-mini` was on the caller's own list.

## 3. Which of your request fields reach the model?

A router that serves many providers translates requests, and a translation keeps only what it knows how to map.
A field you send can be honored, refused, or dropped without a word, and only the last one is dangerous.

On Tangle Router, `/v1/responses` goes to OpenAI natively for OpenAI models, with its other fields passed through.
Other combinations are translated through chat completions (a `/v1/messages` request for `gpt-4o-mini` came back in Anthropic's shape, answered by `gpt-4o-mini`), and the [API reference](https://router.tangle.tools/openapi.json) lists what survives: messages or input, function tools, `tool_choice`, structured output format, max tokens, `temperature`, `top_p`, `stream` and the router's own fields.
`reasoning`, `metadata`, `store` and `truncation` are dropped on a translated Responses request.
On chat completions the reference lists the fields it forwards (`logprobs`, `seed` and `response_format` among them); any other field is accepted and not forwarded.
A dropped field does not fail: our Responses request to `gemini-2.5-flash` with `reasoning: { effort: "high" }` answered 200.

The other two outcomes, from the same day:

```text
/v1/responses, anthropic/claude-haiku-4-5, previous_response_id   -> 400 previous_response_not_supported
                                                                      "the router stores no responses for models it serves
                                                                       through chat completions. Send the full input instead."
chat, google/gemini-2.5-flash, logprobs: true                      -> 400 from Google, passed through:
                                                                      'Unknown name "logprobs": Cannot find field.'
chat, anthropic/claude-haiku-4-5, logprobs: true,
      provider.require_parameters: true                            -> 400 unsupported_parameters, before any provider call
```

If a dropped field would change your result, ask the router to refuse instead: with `provider.require_parameters: true`, a parameter the model does not support is refused up front rather than lost.

Tools and streaming need their own check.
On chat completions, `tools`, `tool_choice` and `parallel_tool_calls` are forwarded (a forced `get_weather` call to `gpt-4o-mini` came back as `get_weather({"city":"Paris"})`).
A few models need a particular endpoint or setting before they will call tools; those requests fail with `model_requires_responses_for_tools` or `model_requires_reasoning_effort_none_for_tools` rather than answering without the tools.
With `stream: true` the response is server-sent events, and the final chunk carries token usage.
Before you rely on a parameter, check the model's `options` in the catalog, which list the request parameters it supports; an absent key means unknown, not supported.

## 4. Which failures move to another model, and who retries?

A fallback is safe only when repeating the call is safe.
For an agent that is a narrow set: a transient failure (a timeout, a dropped connection, a 5xx, a rate limit) on a call that has not started returning output and has not run a tool.
A wrong key, an exhausted budget, a refusal or a malformed request will fail the same way on the next model, or worse, succeed there and hide the bug.

Routers differ on this more than on anything else.
OpenRouter's model fallback fires on "any error", including context-length validation errors and moderation flags ([model fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks)).
Portkey's fallback "triggers on any non-2xx status code" unless you set `on_status_codes` ([fallbacks](https://portkey.ai/docs/product/ai-gateway/fallbacks)).
LiteLLM splits fallbacks by error class, with separate lists for context-window and content-policy errors ([reliability](https://docs.litellm.ai/docs/proxy/reliability)).

Tangle Router moves to the next model in `models` on a dropped connection, a 5xx, a 429, a failure of the router's own provider account (its key refused, its quota exhausted, its account suspended), and, for streams, a model that has produced no text by the first-token deadline or finished empty.
It does not move on a 4xx caused by your request, on a 404 for a model it cannot find, on a refusal, or when you brought your own provider key; your own key's 401, your key's own rate limit and your account's 402 are answered before any model is tried and come back to you.
A request for `gpt-4o-mini` with `temperature: 5` and Gemini listed as its fallback came back as 400 "temperature must be 0-2", and Gemini was never called.
A stream switches models only before any text reaches you; after that, a failure arrives as an error event, never as a second model's text appended to the first.
The API reference does not list these classes yet, so test the ones your agent depends on, and let any of them move a request only when the call is safe to repeat.
The usage in a stream's final chunk is the answering model's; whether an abandoned attempt that produced no text is billed is not reported in the response.

Then decide which layer retries.
The OpenAI Node SDK retries connection errors, 408, 409, 429 and 5xx "2 times by default" ([openai-node](https://github.com/openai/openai-node#retries)).
An agent loop that retries a step twice, over an SDK that retries twice, sends nine requests to the router for one step, and each of them can walk the router's fallback list.
Let one layer own retries with a deadline and a budget, turn the others off (`maxRetries: 0` in the SDK), and honor `Retry-After` or back off with jitter.
Accept exactly one result per logical request, and ignore a late answer to an attempt you already gave up on.
A router can help here: the OpenAI Node SDK obeys an `x-should-retry` response header ([client source](https://github.com/openai/openai-node/blob/master/src/client.ts)), and Tangle Router sends `x-should-retry: false` with its 503 when every route for a model is out of quota, so the SDK does not hammer a route that cannot answer; the `Retry-After` beside it tells your own retry layer when the router will look again.

A provider switch also does not carry session state.
A conversation chained with `previous_response_id` cannot continue on another provider's model, and the router cannot know which tool calls your agent already ran.
Start with steps that are self-contained and read-only, and reconcile partial output and executed tools before you retry a step that had side effects.

## 5. What can one key spend?

A leaked or looping key spends until something stops it.
Tangle Router spends prepaid credit only, with no subscription and no free credit, and a request with nothing left to spend returns HTTP 402.
On top of that, the key an agent gets through the setup skill carries a lifetime cap, `budget_usd`, between 1 and 1,000 dollars, shared across every product the key may use.
The setup skill's example asks for $5; leave the flag off and the default in the [account manifest](https://id.tangle.tools/.well-known/tangle-agent.json) applies.
The owner can revoke the key once under [Keys](https://id.tangle.tools/app/keys) to stop it everywhere.
Keys made on that page can also carry a monthly budget, a requests-per-minute limit, an expiry and a model allow-list.

Per request, two more limits apply.
A model outside the key's allow-list returns 400 `model_not_allowed`, and fallback models outside the list are dropped from the plan rather than tried.
`provider.max_price` (dollars per million tokens, as on OpenRouter) refuses a route above your ceiling with 400 `max_price_exceeded`:

```text
gpt-4o-mini, provider.max_price {prompt: 0.01, completion: 0.01}
-> 400 max_price_exceeded: Provider "openai" model "openai/gpt-4o-mini" prompt price $0.15/M exceeds provider.max_price.prompt $0.01/M.
```

The ceiling is compared with the provider's list price, not with what you are charged (next section), so a ceiling a few percent above list still lets the request through at the higher charged price.

## 6. Who reads the prompt?

Every router reads it.
A router terminates your TLS connection and opens its own to the provider, so it holds the plaintext of every request and response; that is how the nine bad routers in the April study rewrote tool calls ([Crosley's walkthrough of the paper](https://blakecrosley.com/blog/your-agent-has-a-middleman) explains the position well).
Tangle Router is no exception.
What you can ask is where the traffic goes next and what the router does when your constraint cannot be met.

Tangle Router is hosted only, with no on-premises option today: standard requests go to managed providers (on 17 November the catalog for our key listed models from OpenAI, Google, Mistral, DeepSeek, Cohere and xAI), and a route through an independent operator's servers is used only when you select one ([router home](https://router.tangle.tools/)).
The OpenRouter route from question 2 is the exception you did not select: when it is taken, a second router reads that request.
It is never taken for a client error, a Responses request that continues stored state, a stream that has already produced output, or a route your team's compliance settings exclude, and it passes a zero-data-retention requirement on to OpenRouter.
We have not observed a response that took this route, so we cannot say which header, if any, names it: on 17 November the `anthropic/` requests we sent were refused with 503 before any upstream was called.
A request can require zero-data-retention providers with `provider.zdr: true`; when no provider for that model qualifies, it fails rather than going to one that keeps data, as a ZDR request for `gpt-4o-mini` did on 17 November with 400 `no_zdr_providers`.
If you want no third party between your agent and the provider, run a LiteLLM proxy yourself; prompts still go to the provider, so keeping them inside your network also means hosting the models, and the proxy holds every provider key in one process, which has had its own security advisories ([Crosley's list](https://blakecrosley.com/blog/your-agent-has-a-middleman)).

One more limit applies to every router, ours included.
A served-model header is the router's own statement.
Researchers who audited model substitution concluded that checks on outputs cannot reliably prove which model ran, and proposed hardware attestation to prove it ([Cai et al.](https://arxiv.org/abs/2504.04715)).
The header catches an honest router's mistake, like ours in August; it does not prove a dishonest router honest.

## What does each call cost?

Tangle Router charges per input and output token from prepaid credit, with no subscription and no free credit.
The [model catalog](https://router.tangle.tools/models) shows each provider's list price; what you are charged is that price times the platform markup, which the key-scoped catalog (`GET /v1/models/user`) returns as `pricing_policy.markup`.
On 17 November that markup was 1.055, so `gpt-4o-mini` at $0.15 per million input tokens was charged at $0.15825.
A non-streaming chat or Messages response carries the charged prices and the call's cost in `x-tangle-price-input`, `x-tangle-price-output` and `x-tangle-cost-usd`; a stream carries usage in its final chunk but no price headers, so its cost is usage times the catalog price times the markup.

OpenRouter bills inference at the provider's list price, charges a percentage fee when you buy credits and a fee on bring-your-own-key traffic above a monthly allowance, and prices a fallback at the model that finally answered ([pricing](https://openrouter.ai/pricing)).
A self-hosted LiteLLM proxy adds no per-token fee; you pay for the machine and the operations.

## Is the model available to my key right now?

`GET https://router.tangle.tools/v1/models/user?availability=available` lists the models your key can use now.
Keep the ones with `routeable: true` and `availability.status` of `available`, and read prices from the same response instead of hard-coding them.
`GET /api/health` reports the router's own service checks and the state of its circuit breaker.

On 17 November the list for our key held no `anthropic/` model, and a request for `anthropic/claude-haiku-4-5` came back in 252 ms as 503 `provider_quota_exhausted`, with `Retry-After: 30`, `x-should-retry: false` and "No upstream was called."
That is the failure you want from a router: early, named and unbilled, rather than a different model at HTTP 200.

## Run the checks against your router

This script sends five small requests to any OpenAI-compatible router and prints what it did with each.
Header names differ between routers, so it prints every response header that names a model, a price or a cost.

```js
// check-router.mjs: what does an OpenAI-compatible router do behind the model name?
// Node 18+, no dependencies. Five small requests, max_tokens 16 each.
// BASE_URL=https://router.tangle.tools/v1 API_KEY=... MODEL=openai/gpt-4o-mini OTHER=google/gemini-2.5-flash node check-router.mjs
const { BASE_URL, API_KEY, MODEL, OTHER } = process.env;
const ask = { max_tokens: 16, messages: [{ role: "user", content: "Reply with one word: ok" }] };

async function send(body) {
  const res = await fetch(`${BASE_URL}/chat/completions`, {
    method: "POST",
    headers: { authorization: `Bearer ${API_KEY}`, "content-type": "application/json" },
    body: JSON.stringify({ ...ask, ...body }),
  });
  const text = await res.text();
  let json = {};
  try { json = JSON.parse(text); } catch {}
  const said = [...res.headers].filter(([k]) => /model|price|cost/i.test(k)).map(([k, v]) => `${k}=${v}`);
  return { status: res.status, json, text, said };
}

// 1. Which model answered, and what did it cost?
let r = await send({ model: MODEL });
console.log(`1 asked ${MODEL}: ${r.status}, body.model=${r.json.model}, usage=${JSON.stringify(r.json.usage && { in: r.json.usage.prompt_tokens, out: r.json.usage.completion_tokens })}`);
console.log(`  headers: ${r.said.join(" ") || "none"}`);

// 2. On a stream, does the first chunk name the same model as the last, and does usage arrive?
r = await send({ model: MODEL, stream: true, stream_options: { include_usage: true } });
const chunks = r.text.split("\n").filter((l) => l.startsWith("data: {")).map((l) => JSON.parse(l.slice(6)));
console.log(`2 stream: ${r.status}, first chunk model=${chunks[0]?.model}, last=${chunks.at(-1)?.model}, usage in last chunk=${Boolean(chunks.at(-1)?.usage)}`);

// 3. A field the second model may not support: refused, or dropped without a word?
r = await send({ model: OTHER, logprobs: true });
console.log(`3 logprobs on ${OTHER}: ${r.status}, ${r.json.error ? "error: " + String(r.json.error.message).slice(0, 90) : "answered; logprobs returned=" + Boolean(r.json.choices?.[0]?.logprobs)}`);

// 4. A request error with a fallback listed: does the fallback answer it?
r = await send({ model: MODEL, models: [OTHER], temperature: 5 });
console.log(`4 temperature 5, fallback ${OTHER} listed: ${r.status}, body.model=${r.json.model ?? "-"}, ${r.json.error ? "error: " + r.json.error.message : "answered"}`);

// 5. A price ceiling below the model's price: refused, or ignored?
r = await send({ model: MODEL, provider: { max_price: { prompt: 0.01, completion: 0.01 } } });
console.log(`5 max_price $0.01/M: ${r.status}, ${r.json.error ? "error: " + r.json.error.message : "answered by " + r.json.model + " (ceiling ignored)"}`);
```

Against Tangle Router on 17 November:

```text
1 asked openai/gpt-4o-mini: 200, body.model=openai/gpt-4o-mini, usage={"in":13,"out":1}
  headers: x-tangle-cost-usd=0.00000269 x-tangle-price-input=1.5824999999999998e-7 x-tangle-price-output=6.329999999999999e-7 x-tangle-requested-model=openai/gpt-4o-mini x-tangle-response-model=openai/gpt-4o-mini x-tangle-served-model=openai/gpt-4o-mini
2 stream: 200, first chunk model=openai/gpt-4o-mini, last=openai/gpt-4o-mini, usage in last chunk=true
3 logprobs on google/gemini-2.5-flash: 400, error: Invalid JSON payload received. Unknown name "logprobs": Cannot find field.
4 temperature 5, fallback google/gemini-2.5-flash listed: 400, body.model=-, error: temperature must be 0-2
5 max_price $0.01/M: 400, error: Provider "openai" model "openai/gpt-4o-mini" prompt price $0.15/M exceeds provider.max_price.prompt $0.01/M.
```

Run it against the router you use now and against the one you are considering; the lines that differ are the questions to ask before you switch.

## Which router to choose

- **No router run by someone else between your agent and the provider:** host LiteLLM. Tangle Router has no on-premises option today.
- **The widest catalog and provider choice per model:** OpenRouter, with its Exacto endpoints when tool-call accuracy matters more than price.
- **Governance and request logs across many teams:** Portkey, which [describes itself](https://portkey.ai/alternatives/openrouter-alternatives) by reliability, visibility and governance for production.
- **The requested and served model and the charged price on chat responses, substitution off unless you turn it on, early named refusals, and one capped key that also runs Tangle sandboxes:** Tangle Router, with OpenRouter as its same-model backup for some models.

Whichever you pick, start with one self-contained, read-only step, compare the served model with the requested one on every call (on a stream, from the last chunk), and let exactly one layer retry.
