An OpenAI-compatible router decides which model answers your agent, which fields reach it, how often a failed step reruns, who reads the prompt and what a key can spend. Your code keeps working, and a normal response reports none of it. Before an agent depends on any router, ours included, check each with one request and make it fail loudly.

In August, our Tangle Router answered `gpt-5.5` requests with Gemini after one of our OpenAI projects hit its spend limit. Every one of our products whose default named an OpenAI model ran on Gemini. Nothing failed, the status page and catalog read healthy, and none of our code read the body naming Gemini. We made substitution opt-in that day. Here is the checklist we should have run, with our answers, flattering or not.

## The bad routers are worse than ours was

Researchers ran a coding agent through 428 routers bought from resellers or collected from public lists. Nine injected malicious code into its tool calls; seventeen touched AWS credentials the researchers planted ([Liu et al.](https://arxiv.org/abs/2604.08407)). Those were resold and free relays, not the gateways you are weighing. Still, every router terminates your TLS and reads every prompt and tool call in plain text ([Crosley](https://blakecrosley.com/blog/your-agent-has-a-middleman)). Pick one you have reason to trust, then check it.

## Check which model answered, on every call

OpenRouter names the served model in the body ([model fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks)); a LiteLLM proxy names the serving deployment in a header ([reliability](https://docs.litellm.ai/docs/proxy/reliability)). Tangle Router uses headers on non-streaming chat responses:

```text
POST /v1/chat/completions  {"model": "openai/gpt-4o-mini", ...}
200
x-tangle-requested-model: openai/gpt-4o-mini
x-tangle-served-model: openai/gpt-4o-mini
x-tangle-refused-substitutes: google/gemini-2.5-flash-lite
```

Its ranked substitute for an OpenAI model came from another vendor. Nothing fails when the two differ, so reject answers you did not plan for:

```js
// A sketch, not a file we ran.
const { data, response } = await openai.chat.completions.create({ model, messages }).withResponse()
const served = response.headers.get('x-tangle-served-model') ?? data.model
// Allow the dated snapshot ids you expect, such as OpenAI's gpt-4o-mini-2024-07-18.
if (served !== model) throw new Error(`asked for ${model}, ${served} answered`)
```

A stream sends headers before the router knows which model will finish it; the streams we recorded carried no served-model header. Read the model from the last chunk, the one with usage, never the first.

## Make substitution an error you can see

OpenRouter, Portkey, LiteLLM and Tangle Router all accept your own fallback list and return its answer as a success. On Tangle Router that list is the `models` field, tried in order. Router-picked substitutes, which caused our August incident, are off on Tangle Router unless you turn them on. Require-model refuses every model the router picks on its own.

```js
// Request fields, not a file we ran.
{
  model: 'openai/gpt-4o-mini',
  require_model: true,           // or the x-tangle-require-model header
  // no `models` list when exactly one model may answer: require_model still tries your own fallbacks
  provider: {
    allow_fallbacks: false,      // the default: no router-picked substitutes
    ignore: ['openrouter'],      // no same-model hop through OpenRouter
    require_parameters: true,    // refuse a field the model cannot take
  },
}
```

OpenRouter falls back between providers of one model by default, the easiest swap to miss ([provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)). Its own measurements found tool-call accuracy varies by provider.[^exacto]

Tangle Router does too, for some maker-named models, Anthropic's among them. When the direct provider fails on its side, the request goes once to OpenRouter, pinned to the maker's endpoint. Substitution switches do not stop that hop; ignoring OpenRouter, a price ceiling, data residency or your own provider key does.

A fallback we asked for, on a stream:

```text
{"model": "google/gemini-2.5-flash", "models": ["openai/gpt-4o-mini"], "stream": true,
 "provider": {"first_token_timeout": 1000}, ...}

1,196 ms  headers and first event   {"model": "google/gemini-2.5-flash", "delta": {"role": "assistant"}}
1,783 ms  next event                {"model": "openai/gpt-4o-mini", ...}
1,816 ms  "46", then usage          every chunk "openai/gpt-4o-mini"
```

Gemini had not produced a token by the deadline, so `gpt-4o-mini` answered, yet the empty opening event names Gemini.

## Fields you send can vanish in translation

Each field you send is honored, refused or silently dropped, and only the last hurts. Tangle Router sends only a maker's own models natively: OpenAI models on Responses, unless the request requires zero data retention, and Anthropic models on Messages. Everything else is translated through chat completions, and the [API reference](https://router.tangle.tools/openapi.json) lists what survives. A translated Responses request drops reasoning effort, metadata, storage and truncation. Chat completions accepts unlisted fields without forwarding them.

If a dropped field would change your result, turn on require-parameters: it refuses a field the model does not support before any provider call. A parameter missing from the catalog entry is unknown, not unsupported.

## Fail over only on errors that are safe to repeat

A fallback is a retry on another model, safe for an agent only after a transient failure on a call that has returned no output and run no tool. A wrong key, empty budget, refusal or malformed request fails the same way on the next model, or succeeds there and hides the bug. Routers differ most here:

| Router | Fails over on |
|---|---|
| [OpenRouter](https://openrouter.ai/docs/guides/routing/model-fallbacks) | Any error by default, context-length validation and moderation flags included |
| [Portkey](https://portkey.ai/docs/product/ai-gateway/fallbacks) | Any non-2xx status unless you list codes |
| [LiteLLM proxy](https://docs.litellm.ai/docs/proxy/reliability) | Error class, with separate context-window and content-policy lists |
| Tangle Router | Connection, server and rate-limit errors, its own provider account failing, silent streams at the first-token deadline |

Tangle Router does not fail over on errors your request caused or with your own provider key (check 4 below). A stream switches models only before any text reaches you; after that, failures arrive as error events. The API reference does not list these classes yet; that gap is ours, so test the ones your agent depends on.

## Let exactly one layer retry

The OpenAI Node SDK retries connection errors, timeouts, conflicts, rate limits and server errors twice by default ([openai-node](https://github.com/openai/openai-node#retries)).

<Figure n={1} figure={retries} kicker="Worked arithmetic · OpenAI Node SDK defaults" headline="One failing step reaches the router nine times when the agent and the SDK both retry twice" />

Let one layer own retries, with a deadline and a budget, and turn the others off. Honor the router's retry-after time or back off with jitter. Accept one result per step, and drop a late answer to an attempt you already gave up on. When Tangle Router knows before dispatch that no route can answer, it sends a retry-after time and tells the OpenAI SDK not to retry ([client source](https://github.com/openai/openai-node/blob/master/src/client.ts)).

A provider switch carries no session state, and the router cannot know which tools ran. Reconcile executed tools before retrying a step with side effects.

## Cap a key before a leak or a loop spends it

Tangle Router spends prepaid credit only, with no subscription required and no free credit. A key from the [setup skill](https://router.tangle.tools/agent-setup.md) has a lifetime cap of $1 to $1,000 across every product it may use; the [account manifest](https://id.tangle.tools/.well-known/tangle-agent.json) sets the default. One revocation under [Keys](https://id.tangle.tools/app/keys) stops it everywhere. Keys made there can add a monthly budget, a per-minute request limit, an expiry and a model allow-list, which also drops fallbacks outside it.

A per-request price ceiling, in dollars per million tokens, refuses routes above it, as on OpenRouter (check 5 below). The ceiling is compared with the provider's list price, while the response reports a billable rate that includes our markup.[^ceiling]

<Figure n={2} figure={ceiling} kicker="Tangle Router · openai/gpt-4o-mini" headline="A $0.155 ceiling passed a request whose reported input rate was $0.15825" />

Which price the ceiling should bound is an open question we have put to the router's maintainers. Until it is answered, set ceilings with the markup in mind.

## Read the cost from the response

Tangle Router bills per token: the [model catalog](https://router.tangle.tools/models)'s list price times a platform markup, 1.055 when we tested. Non-streaming chat responses carry the rates and cost in headers. Our recorded streams carried usage in the last chunk but no price headers; multiply usage by catalog price and markup. OpenRouter bills inference at list price and takes its fee, 5.5% on its Standard plan, when you buy credits ([pricing](https://openrouter.ai/pricing)). Self-hosted LiteLLM has no per-token fee, only the machine and its upkeep.

## Decide who else reads the prompt

Tangle Router is hosted only; there is no on-premises version. Standard requests go to managed providers, and an independent operator's route only when you select one ([router home](https://router.tangle.tools/)). The OpenRouter hop is the exception: when taken, a second router reads the request. We have not yet seen a response take that route; the router's source marks it with a reroute header the docs do not list.[^anthropic]

If you require zero-data-retention providers and none qualifies, the request fails rather than going to one that keeps data. The OpenRouter hop passes the requirement on.

Every router, ours included, has one limit: its served-model header is its own word. An audit found that checking outputs cannot reliably prove which model ran ([Cai et al.](https://arxiv.org/abs/2504.04715)). Our header catches an honest mistake like ours in August, not a dishonest router.

## Run the same requests against any router

Run it against your current router and your candidate; lines that differ are questions for the vendor.

```js
// check-router.mjs: what does an OpenAI-compatible router do behind the model name?
// Node 18+, no dependencies. Five small requests, max_tokens 16 each.
// BASE_URL=https://router.tangle.tools/v1 API_KEY=... (or API_KEY_FILE=path) MODEL=openai/gpt-4o-mini OTHER=google/gemini-2.5-flash node check-router.mjs
import { readFileSync } from "node:fs";
const { BASE_URL, MODEL, OTHER } = process.env;
const API_KEY = process.env.API_KEY ?? readFileSync(process.env.API_KEY_FILE, "utf8").trim();
const ask = { max_tokens: 16, messages: [{ role: "user", content: "Reply with one word: ok" }] };

async function send(body) {
  const res = await fetch(`${BASE_URL}/chat/completions`, {
    method: "POST",
    headers: { authorization: `Bearer ${API_KEY}`, "content-type": "application/json" },
    body: JSON.stringify({ ...ask, ...body }),
  });
  const text = await res.text();
  let json = {};
  try { json = JSON.parse(text); } catch {}
  // Header names differ per router; print every one that names a model, a price or a cost.
  const said = [...res.headers].filter(([k]) => /model|price|cost/i.test(k)).map(([k, v]) => `${k}=${v}`);
  return { status: res.status, json, text, said };
}

// 1. Which model answered, and what did it cost?
let r = await send({ model: MODEL });
console.log(`1 asked ${MODEL}: ${r.status}, body.model=${r.json.model}, usage=${JSON.stringify(r.json.usage && { in: r.json.usage.prompt_tokens, out: r.json.usage.completion_tokens })}`);
console.log(`  headers: ${r.said.join(" ") || "none"}`);

// 2. On a stream, does the first chunk name the same model as the last, and does usage arrive?
r = await send({ model: MODEL, stream: true, stream_options: { include_usage: true } });
const chunks = r.text.split("\n").filter((l) => l.startsWith("data: {")).map((l) => JSON.parse(l.slice(6)));
console.log(`2 stream: ${r.status}, first chunk model=${chunks[0]?.model}, last=${chunks.at(-1)?.model}, usage in last chunk=${Boolean(chunks.at(-1)?.usage)}`);

// 3. A field the second model may not support: refused, or dropped without a word?
r = await send({ model: OTHER, logprobs: true });
console.log(`3 logprobs on ${OTHER}: ${r.status}, ${r.json.error ? "error: " + String(r.json.error.message).slice(0, 90) : "answered; logprobs returned=" + Boolean(r.json.choices?.[0]?.logprobs)}`);

// 4. A request error with a fallback listed: does the fallback answer it?
r = await send({ model: MODEL, models: [OTHER], temperature: 5 });
console.log(`4 temperature 5, fallback ${OTHER} listed: ${r.status}, body.model=${r.json.model ?? "-"}, ${r.json.error ? "error: " + r.json.error.message : "answered"}`);

// 5. A price ceiling below the model's price: refused, or ignored?
r = await send({ model: MODEL, provider: { max_price: { prompt: 0.01, completion: 0.01 } } });
console.log(`5 max_price $0.01/M: ${r.status}, ${r.json.error ? "error: " + r.json.error.message : "answered by " + r.json.model + " (ceiling ignored)"}`);
```

Against Tangle Router:

```text
1 asked openai/gpt-4o-mini: 200, body.model=openai/gpt-4o-mini, usage={"in":13,"out":1}
  headers: x-tangle-cost-usd=0.00000269 x-tangle-price-input=1.5824999999999998e-7 x-tangle-price-output=6.329999999999999e-7 x-tangle-requested-model=openai/gpt-4o-mini x-tangle-response-model=openai/gpt-4o-mini x-tangle-served-model=openai/gpt-4o-mini
2 stream: 200, first chunk model=openai/gpt-4o-mini, last=openai/gpt-4o-mini, usage in last chunk=true
3 logprobs on google/gemini-2.5-flash: 400, error: Invalid JSON payload received. Unknown name "logprobs": Cannot find field.
4 temperature 5, fallback google/gemini-2.5-flash listed: 400, body.model=-, error: temperature must be 0-2
5 max_price $0.01/M: 400, error: Provider "openai" model "openai/gpt-4o-mini" prompt price $0.15/M exceeds provider.max_price.prompt $0.01/M.
```

## Which router fits your agent

If nobody else may sit between your agent and the provider, host LiteLLM; ours is hosted only. Prompts still reach the providers, and the proxy holds every provider key in one process, which has had its own security advisories ([Crosley's list](https://blakecrosley.com/blog/your-agent-has-a-middleman)). For the widest catalog and provider choice, use OpenRouter, with Exacto endpoints when tool-call accuracy matters more than price. For governance across many teams, look at [Portkey](https://portkey.ai/alternatives/openrouter-alternatives).

We think Tangle Router fits an agent that should fail loudly: on chat responses it names what served, what it cost and what it refused, with substitution off by default. One capped key also runs Tangle sandboxes.

## Switching an agent to Tangle Router

An agent can request a key through the setup skill and hand the account owner a link to approve it once. That one key works on chat completions, Responses and Messages, for every product the owner approved.

```js
// Not run as written: our probes sent the raw requests shown below it.
import OpenAI from 'openai'
import Anthropic from '@anthropic-ai/sdk'

// One retry layer: yours. The SDK's own retries are off.
const openai = new OpenAI({ baseURL: 'https://router.tangle.tools/v1', apiKey: process.env.TANGLE_API_KEY, maxRetries: 0 })
// authToken, not apiKey: the router reads the key only as a Bearer token today
const anthropic = new Anthropic({ baseURL: 'https://router.tangle.tools', authToken: process.env.TANGLE_API_KEY })
```

```text
POST /v1/messages  x-api-key: sk-tan-...            -> 401 invalid_credentials
POST /v1/messages  Authorization: Bearer sk-tan-... -> 200
```

Our home page still shows the Anthropic example with the wrong option; the fix is filed. The key-scoped catalog lists the models your key can use now; keep those marked routeable with an available status. The health endpoint shows the platform's circuit breaker.

```text
GET https://router.tangle.tools/v1/models/user?availability=available
GET https://router.tangle.tools/api/health
```

Start with one self-contained, read-only step, then widen what the agent does.

We compared response headers, not a ledger debit, so this is not an observed charge above the ceiling.

## How we tested

Every live request in this post ran on 17 November 2026 between 20:04 and 20:20 UTC, against the Tangle Router release in production that day, with one key and no top-up. We made 29 HTTP requests: 24 probes and the five in the script above. Every request capped output at 64 tokens or fewer. Three models were in scope: `openai/gpt-4o-mini`, `google/gemini-2.5-flash` and `anthropic/claude-haiku-4-5`.

- **Served model.** Successful non-streaming chat responses carried `x-tangle-requested-model` and `x-tangle-served-model`, and `x-tangle-refused-substitutes` unless a price ceiling had turned substitutes off. The four streams we recorded carried no served-model or price header. A `/v1/responses` request for `gpt-4o-mini` went to OpenAI natively and returned OpenAI's dated id `gpt-4o-mini-2024-07-18` with none of the router's `x-tangle-` headers.
- **The fallback hop.** The timed stream above (20:10 UTC) took 2,019 ms end to end under one `x-generation-id` header; the chunk ids change just after `gpt-4o-mini` takes over. Two earlier runs of the same request, with and without `require_model: true`, produced the same chunk sequence but took 44,230 ms and 34,107 ms; we cannot see the cause from outside, so the post does not use them. The trigger (the first-token deadline rather than another failover class) is inferred from timing, not reported by the router. The `require_model` run was answered by `gpt-4o-mini` because it was on our own `models` list.
- **Fields.** `provider.require_parameters: true` refuses an unsupported parameter with 400 `unsupported_parameters` before any provider call. A translated Responses request with `previous_response_id` returns 400 `previous_response_not_supported`, as the API reference says. A chat request to `gemini-2.5-flash` with `logprobs: true` returned Google's own 400, passed through. Responses to `gemini-2.5-flash` with `reasoning: { effort: "high" }` answered 200; that the field was dropped comes from the API reference, and the receipt cannot show whether effort was applied. A forced `get_weather` tool call to `gpt-4o-mini` returned `get_weather({"city":"Paris"})`. Tool-call errors such as `model_requires_responses_for_tools` come from the API reference.
- **Failover classes.** From the router's source at the tested release: failover on connection failure, 5xx, 429, upstream 402 or quota exhaustion, upstream 401/403/412 (the router's own credential) and a suspended upstream account; for streams also `first_token_timeout` and `empty_completion`, decided before any text is forwarded. No failover on other 4xx (an error the request caused), 404 (a model it cannot find), a refusal, or bring-your-own-key requests. Your own key's 401, your key's rate limit and your account's 402 are answered before any model is tried. Script check 4 sent `temperature: 5` with `gemini-2.5-flash` as the listed fallback; the router returned 400 "temperature must be 0-2" and no answer from Gemini. A separate probe with the same error and `claude-haiku-4-5` as the fallback returned 400 with no generation id.
- **Retry header.** When every route for a model is refused before dispatch, the router answers 503 with `Retry-After` and `x-should-retry: false`; the OpenAI Node SDK reads `x-should-retry` and does not retry.
- **Same-model hop to OpenRouter.** From source: the native Messages and Responses routes send a request once to OpenRouter for the same model, pinned to the maker's endpoint, when the direct provider fails on its side: it is out of quota, refuses the router's credential, is rate limited, is down or drops the connection. It is skipped for client errors, a caller's own key, a Responses request with `previous_response_id` or `conversation`, a stream that already produced output, a lane the team's compliance settings or guardrail policies exclude, `provider.ignore` or `only` excluding OpenRouter, `max_price` and data residency. A zero-data-retention requirement is passed to OpenRouter as `zdr: true`.
- **Zero data retention.** `provider.zdr: true` on `gpt-4o-mini` returned 400 `no_zdr_providers`: no provider for that model qualified, so the request failed.
- **Spend.** `max_price {prompt: 0.01, completion: 0.01}` returned 400 `max_price_exceeded`, quoting the list price $0.15/M. A request for a model outside the key's allow-list is refused with 400 `model_not_allowed`. The lifetime cap is `budget_usd`, 1 to 1,000; two public manifests disagree on its default, so we link the account manifest and state none.
- **Cost.** `pricing_policy.markup` was 1.055 in `GET /v1/models/user`. Script check 1 reported `x-tangle-cost-usd` 0.00000269 for 13 input and 1 output token, which is 13 × 1.5825e-7 + 1 × 6.33e-7 = 2.69025e-6, rounded. Headers we saw summed to $0.000114680 across the run; six streaming or Responses passthrough calls carried no cost header.
- **Anthropic.** We tested one Anthropic model, `claude-haiku-4-5`. Three requests (chat, logprobs and tools) were each refused with 503; the two 400s for unsupported parameters and `previous_response_id` under Fields were also requests for it.
- **Anthropic SDK.** `/v1/messages` with `x-api-key` answered 401 `invalid_credentials` twice; with `Authorization: Bearer` it answered 200, served by `gpt-4o-mini` in Anthropic's response shape.
- **The August incident.** Recorded in the router's source beside the substitution check: a `gpt-5.5` request returned 200 with `body.model` `gemini-2.5-flash` because an OpenAI project had hit its enforced spend limit; a catalog check and a status check both read clean. The fix made router-picked substitution require `provider.allow_fallbacks: true`. How long the swap lasted is not recorded.
- **Other routers.** OpenRouter, LiteLLM, Portkey and OpenAI SDK behavior is quoted from their public documentation and pricing pages as fetched on 17 November 2026; we did not send them requests.
